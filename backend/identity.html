Strategic Security Understanding for AVO Platform

Addressing organizational agility, competitive tender secrecy, and fraud prevention.

1. Decoupled 3D User Architecture

Traditional ERPs hardcode roles like "Senior Service Engineer" into database code. When AVO re-organizes, development is required. By decoupling into Role Type (screens), Scope (region/branch), and Level (signing limits), adding a designation takes 60 seconds in the admin UI without code changes.

2. The Bidding "Chinese-Wall"

In high-stakes power tenders (NTPC, Railways, Telecom), AVO frequently quotes 2 or 3 competing system integrators bidding for the same contract. Salesperson A must never know what pricing Salesperson B offered. The platform maintains total blindness between them while giving the Owner unified visibility.

3. Anti-Collusion Scrap Isolation

Valuable materials (copper coils, tested battery cells, salvageable PCBs) represent significant fraud risk. Allowing warehouse operators to view running scrap balances enables reconciliation evasion. The Blind Scrap Entry pattern ensures staff can record entries, but only the CFO/Owner sees totals.

4. Zero-Trust API Enforcement

Security is never implemented by merely hiding UI buttons in CSS. Every REST endpoint verifies JWT scope and level against database queries. If an engineer crafts a manual API request to view another region's tickets, the API immediately rejects the call.

Client Discussion Points & Confirmation Highlights

Directly addressing notes from the FRS sheet: "Need to Discuss More" & "Need to Confirm what we understood".

1. Discussion Point: User Model `Role Type + Scope + Level` (SS-23, SS-35)

What We Understood: AVO has 14 original organizational designations, but job titles frequently evolve across regions. Creating custom code for each title creates software bloat.
Our Confirmation: We have verified that all 14 designations map seamlessly to the 3 attributes. For example, a Senior Solar Engineer is simply Role Type: Project | Scope: South Region | Level: L2. Zero custom code is needed to add future titles.

2. Confirmation Point: API-Layer Enforcement (SS-24)

What We Understood: Hiding a menu item in JavaScript is unsafe. Field technicians or third-party integrators could bypass client-side restrictions.
Our Confirmation: The backend middleware inspects token scope on every HTTP request. Even if a user alters the frontend URL, unauthorized data access returns an immediate HTTP 403 Forbidden.

3. Discussion Point: Scrap Blind Entry (RA-07, RA-08)

What We Understood: Allowing warehouse workers to view running scrap numbers enables theft and reconciliation tampering.
Our Confirmation: The warehouse screen acts as a write-only drop box. Operators can enter what is scrapped today, but historical records and cumulative scrap value are visible only to Owner, CFO, and COO.

4. Confirmation Point: Silent RFP Deduplication (RA-04, RA-05)

What We Understood: When AVO quotes two competing integrators for one tender, salespeople must be isolated, but management hit rate metrics must not be artificially inflated.
Our Confirmation: The system automatically links quotations sharing the same RFP number in the background, surfaces side-by-side comparisons to the Owner, and records the company hit rate once.
